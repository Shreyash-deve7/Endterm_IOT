When two clients disconnect simultaneously, a race condition can occur on the shared clients list. Both threads try to remove their entry at the same time — each reads the list, removes its own client, and writes it back. Since this operation is not atomic, one thread's update can overwrite the other's, leaving a disconnected client still in the list or causing the server to crash. This can be resolved using threading.Lock() by wrapping the modification in a lock (with lock: clients.remove(client)), which ensures only one thread can update the shared list at a time, while the other waits, preventing the lost-update problem.
